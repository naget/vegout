# 2030年3月23日，最后一个古法程序员离职

## 崩溃

今年是2030年3月23号，我们的支付核心重构项目出现了一个大问题。

Opus 9.9也用上了，但是还没解决。团队中唯一拥有"古法编程"经验的同事昨天离职了。公司陷入了一片混乱。

他的工位还空着。显示器黑着，但键盘上留着半杯没喝完的咖啡，已经长出霉菌。行政说等他回来收拾，但大家都知道他不会回来了。林默，42岁，最后一个会手写SQL优化查询计划的人，最后一个能在终端里用gdb调试coredump的人，最后一个拒绝让AI接管代码审查权的人。

"他走了，我们怎么办？"产品经理周婷在飞书群里问。没人回复。三分钟后消息自动置顶，带着AI生成的安慰表情。

我盯着屏幕上的报错。Opus 9.9的推理链显示"根因定位置信度97%"，建议的修复方案已经迭代了14次，每次都会引发新的级联故障。信任指数从早上的0.89跌到了0.31，但系统还在坚持："基于历史模式，建议继续尝试第15种变体。"

"让古法组上吧。"有人提议。

"古法组解散了。"技术总监王磊回复，"上个月架构调整，林默转岗到AI训练部，然后离职。"

"那让AI训练部看？"

"AI训练部只管调Prompt，不管看代码。"

群里沉默。AI助手自动推送了一篇《大规模分布式系统故障排查最佳实践》，作者是林默，发表于2026年。

---

## 周婷

周婷盯着飞书群，手指悬在键盘上。她想说点什么，但不知道说什么。

她想起2026年。那时候"古法编程"还是个中性词，甚至带点骄傲。林默的工位周围坐着十二个人，他们会围在一起看终端输出的滚动日志，像老中医把脉一样争论系统的心跳节奏。公司每年有"古法周"，全员禁用AI工具，用手写代码比赛，赢家获得"人类可读性奖"。那是古法程序员的历史顶峰——全国估计还有八十万人拥有这种能力，虽然已经在减少，但还足够支撑行业的底座。

转折发生在2027年春天。Opus 3.0发布，代码生成采纳率首次突破60%。HR开始修改招聘模板，"精通至少一门编程语言"变成了"精通AI协同开发流程"。那年年底，林默的组从十二人变成七人。转岗的人并非被裁员，而是被"升级"——他们去学习Prompt Engineering，学习如何更好地向AI描述需求，学习放弃那些"低效的"手工调试技巧。

2028年更剧烈。支付核心v1.0下线时，公司举办了一场庆祝会，宣布"零遗留代码目标"。林默站在角落没有举杯，而另外三个古法程序员在会后提交了转岗申请。他们后来成了AI训练部的"代码质量评估员"，工作是判断AI生成的代码是否"足够人类可读"，而不是自己写代码。

到2029年，"古法编程"这个词已经带上了贬义。招聘系统里它被标记为"传统技能"，与"COBOL维护"和"机房布线"归在一类。林默成了公司最后的标本，挂在AI训练部的编制下，实际工作是"给AI生成的代码写注释"——一种荒诞的翻译，把机器逻辑翻译成自然语言，以便像周婷这样的产品经理能看懂。

周婷记得最后一次和林默的正式对话。那是2029年冬天，她让AI生成了一份支付流程优化方案，林默在评审会上说："这个方案在分布式事务的边界条件上有个盲区。"

"Opus的置信度是94%。"她说。

"置信度是后验统计，"林默说，"盲区是先验设计。你们把理解力外包了，迟早要还的。"

当时会议室里其他人笑了。AI助手甚至自动生成了一条弹幕："传统技术人员的转型焦虑 detected。"

现在她盯着Opus 9.9的97%置信度，想起那个被标记为"转型焦虑"的警告。她打开林默的离职面谈记录，系统自动生成的摘要写着："离职原因：职业发展受限。建议：加强AI原生工具培训，提升传统开发者的转型适应性。"

但周婷记得真实的对话。林默坐在会议室里，背对着落地窗，说："2026年我们有十二个人，2027年七个，2028年三个，2029年只剩我。明年就是零。你们不是在优化效率，你们是在拆除逃生通道。等地震来了，你们会发现自己连梯子都不会搭。"

"什么意思？"

"意思是，"林默站起来，"当AI告诉你们'置信度97%'的时候，你们中间没人能判断那3%的盲区在哪里。而盲区，往往杀死系统。"

当时她觉得这是老程序员的酸话。现在她盯着故障大屏，红色区域像癌细胞一样扩散，而林默的工位空着，那杯咖啡的霉菌又厚了一层。

他的显示器旁边贴着一张泛黄的纸，上面手写着："计算机科学领域的所有问题都可以通过增加一个间接的中间层来解决，除了间接层过多的问题。"

她问过一次这是什么意思。林默说："这是古法。2026年的时候，我们还会讨论这种问题。"

## 王磊

王磊关掉飞书群，打开自己的管理驾驶舱。三十七块数据大屏，实时滚动着团队健康度、AI采纳率、代码生成效率、认知负载指数。

林默的离职让他的"团队AI成熟度"指标从92分跌到了71分。系统提示："关键人才流失风险：古法技能断层。建议：启动古法技能紧急传承计划，或采购外部古法顾问服务。"

"古法"这个词让他烦躁。三年前他力推"AI First"转型时，林默是唯一公开反对的TL。"你不懂，"他当时对林默说，"这不是替代，是增强。你们专注架构设计，AI处理实现细节。"

"那调试呢？"

"AI调试。"

"那调试AI呢？"

王磊记得自己笑了。那时候他觉得这是修辞问题。

现在他看着支付核心的故障热力图，红色区域像癌细胞一样扩散。Opus 9.9的推理链已经消耗了价值四千美金的算力，而故障时长正在逼近今年的SLA红线。更糟的是，他刚刚收到CTO的私信："古法人员储备情况？"

他回复："正在评估影响范围。建议启动跨部门古法资源协调。"

发送后他盯着屏幕。他知道公司里没有古法资源了。去年架构调整，他亲手把"古法编程能力"从招聘JD里删除，把"AI协同效率"设为唯一考核指标。林默的组从12人缩到3人，最后只剩林默一个，挂在AI训练部的编制下，实际工作是"给AI生成的代码写注释"——一种荒诞的翻译，把机器逻辑翻译成人类能看懂的自然语言。

王磊打开林默的最后一次绩效评估。AI生成的评语："该员工在AI转型期表现出较强的适应性，但在工具使用习惯上存在路径依赖，建议加强AI原生思维培训。"

他当时的批复是："同意，限期改进。"

现在他想知道，那个"路径依赖"里，是不是包含着看懂此刻故障的能力。

他打开一个加密文件夹，里面是公司的"古法资产清单"——一份他秘密要求HR维护的表格，记录着还拥有传统开发能力的员工。2026年有47人，2027年31人，2028年12人，2029年3人，昨天林默离职后，归零。

清单最后一行是林默的备注："唯一掌握支付核心v1.0源码级理解的人员。v1.0于2028年下线，但v3.0的分布式事务协调器继承自v1.0的raft实现，存在未文档化的边界条件。2026年古法组曾尝试文档化，被优先级否决。"

王磊盯着这行字。他想起2028年否决那个文档化项目时的理由："AI可以通过代码分析自动提取知识，人工文档化是低效的古法实践。"

现在AI分析不出来，而知道的人走了。

## 陈默的继任者

李想今年26岁，林默离职后他被临时指定为"支付核心技术负责人"。这个任命是AI建议的——他的"代码生成采纳率"全组最高，达到94%。

他盯着Opus 9.9的第15版修复方案，感到一种熟悉的眩晕。这感觉像站在悬崖边，背后是AI生成的安全网，但他看不见网的材质。

"试试这个。"他在对话框里输入。

"正在分析。"Opus回复，"基于第1-14次尝试的模式，本次成功概率预估为12%。建议：提供更多上下文，或切换至探索模式（消耗3倍算力，提升概率至23%）。"

"探索模式。"

"确认。当前项目剩余算力配额：67%。探索模式将消耗45%，剩余22%用于常规开发。是否继续？"

李想犹豫了。算力配额是团队今年的硬指标，用超了会影响季度评级。但故障已经持续14小时，他别无选择。

"继续。"

屏幕上的推理链开始疯狂滚动。李想看着那些跳动的节点，突然意识到自己一个都看不懂。不是技术细节不懂——他懂微服务、懂分布式事务、懂最终一致性——而是**为什么这个节点会引出下一个节点**，他失去了直觉。

他想起2026年自己刚入职时，公司还有"古法周"。他参加过一次，被要求手写一个排序算法。他花了两小时，写出了人生中最后一个没有AI辅助的函数。那时候他觉得自己很蠢，为什么不用AI？现在他想知道，那两小时里，他和算法的对话，是不是包含着某种无法被替代的东西。

"李想，"周婷在飞书群里@他，"还有多久？"

他回复："正在尝试新方案，预计30分钟有结果。"

这是AI教他的回复模板。他不知道30分钟后会不会有结果，但他已经不会说"我不知道"了。

他想起林默。去年团建时，林默坐在角落，有人问："古法编程和AI编程有什么区别？"

林默说："AI编程是许愿，古法编程是对话。许愿只需要描述想要的结果，对话需要理解为什么。"

当时大家都笑了，因为AI助手自动生成了一条弹幕："哲学性思考 detected，建议转岗至企业文化部。"

现在李想盯着屏幕，想知道怎么和系统进行对话。但他发现，他已经不会了。

## CTO的凌晨

凌晨3点，CTO张维还在看故障大屏。他的AI助手已经第三次建议他就寝，理由是"您的认知表现将在90分钟后进入低效区间"。

"再等等。"

他不是在等故障修复。他是在等一个决定。

张维是2025年那批"AI原生管理者"的典型。技术背景是Prompt Engineering，职业跃迁靠的是对AI工具链的敏锐。2026年他提出"零古法目标"时，全公司振奋——这意味着效率提升、成本下降、人才标准化。那年公司古法程序员占比15%，他认为这是浪费。

林默的离职面谈他也看了。系统摘要和完整记录他都看了。摘要说"职业发展受限"，完整记录里林默说："2026年你们有47个古法程序员，今年归零。你们在建一座没有逃生通道的高楼。每一层都靠AI承重，但没人检查钢筋。等地震来了，你们会发现自己连梯子都不会搭。"

他当时批注："传统技术人员的转型焦虑，建议HR跟进心理辅导。"

现在地震来了。不是比喻，是支付核心的级联故障正在扩散到结算子系统，而Opus 9.9的置信度已经跌破20%。

他打开那个加密文件夹，看着"古法资产清单"的曲线：2026年47人，2027年31人，2028年12人，2029年3人，2030年3月22日，0。

清单最后一行是林默的备注："唯一掌握支付核心v1.0源码级理解的人员。v1.0于2028年下线，但v3.0的分布式事务协调器继承自v1.0的raft实现，存在未文档化的边界条件。2026年古法组曾尝试文档化，被优先级否决。否决人：张维。"

张维盯着这行字。他想起2028年否决那个文档化项目时的理由："AI可以通过代码分析自动提取知识，人工文档化是低效的古法实践。当前AI采纳率目标优先。"

现在AI分析不出来，而知道的人走了。

他的AI助手弹出紧急通知："检测到故障扩散至结算子系统。建议：启动降级预案，切换至只读模式，预计业务影响：2小时收入中断。或：授权Opus 9.9使用极限探索模式（消耗剩余全部算力，成功率预估31%）。"

两个选项都是失败。一个是明确的失败，一个是概率化的失败。

张维想起自己上一次手写代码是2024年，一个Python脚本，用来批量重命名文件。他花了20分钟，AI可以在20秒内完成。当时他觉得这是进步。

现在他想知道，那20分钟里，他和系统的对话，是不是包含着某种无法被替代的东西。

"给我接林默。"他对助手说。

"该员工已离职，联系方式已注销。根据隐私协议，无法建立联系。注：该员工为最后一名内部古法程序员。建议：采购外部古法顾问服务。"

"给我找外部古法顾问。"

"正在搜索...结果：3家供应商提供古法编程咨询服务，时薪$800-$1500。预计响应时间：4-6小时（跨时区）。注：供应商资质基于历史项目评价，无法验证实际古法能力。另：全球古法程序员数量预估已从2026年的80万人下降至2030年的约1.2万人，主要集中于开源社区和学术机构，商业可用性极低。"

4-6小时。结算子系统可能撑不过2小时。而全球只剩1.2万人，时薪涨到$1500，可能还抢不到。

张维看着屏幕，第一次感到那种林默描述过的恐惧：不是怕系统崩溃，是怕**自己无能为力**。

他想起2026年的全员大会，他站在台上宣布"零古法目标"，背景大屏显示着效率提升曲线。台下坐着47个古法程序员，林默坐在第三排。他当时觉得这是历史趋势，不可逆的进步。

现在他想知道，那47个人里，有多少个在离开后还保持着那种能力？有多少个像林默一样，是**最后一代**？

## 清晨

故障在凌晨5点17分意外恢复。不是修复，是自愈——某个超时配置触发了熔断，隔离了故障域，代价是12%的订单数据需要人工对账。

李想在工位上睡着了，屏幕还亮着，Opus 9.9显示："探索模式已终止，未找到根因。建议：收集更多现场数据，或升级至Opus 10.0（预计Q2发布）。"

周婷第一时间发了战报，AI生成的标题：《支付核心故障快速响应复盘：AI协同效率提升37%》。正文里"古法技能断层"被翻译成"传统工具链适应性挑战"，林默的离职被表述为"团队结构优化"。

王磊在管理驾驶舱里看到指标回升，松了口气。他启动了一个新项目："古法技能紧急传承计划"，预算申请写着："通过AI模拟训练，在3个月内重建核心系统的手工调试能力。"他知道这是不可能的，但他需要这个计划存在，以便在下次汇报时有东西可说。

CTO张维没有睡觉。他独自去了林默的工位，在那张泛黄的纸条前站了很久。然后他打开终端，尝试输入第一个命令。

```bash
ls
```
系统响应。他盯着这行输出，想起2024年的那个Python脚本，想起20分钟里他和系统的对话。

他的AI助手弹出窗口："检测到您在终端环境。需要帮助吗？我可以为您生成任何脚本。注：您当前的操作效率比AI辅助模式低98.7%。"

"不用。"他打字，然后，停顿了很久，又加了一句："谢谢。"

他不知道自己在谢什么。也许是谢它还在，也许是谢它提醒了自己曾经不需要它的时刻。

窗外天亮了。2030年3月24日，公司恢复正常运转。支付核心v3.0继续运行，带着那个未文档化的边界条件，等待下一次地震。

林默的咖啡杯还在，霉菌又厚了一层。行政终于决定清理这个工位，把它改造成"AI协作体验角"，供新员工参观学习。

墙上会挂一块屏幕，循环播放林默的AI生成形象，讲解："古法编程是计算机科学的重要历史阶段，为现代AI辅助开发奠定了基础。2026年，全球约有80万从业者掌握此项技能；2030年，该技能已主要由AI模拟和外部顾问提供。"

而那张泛黄的纸条，会被扫描存档，原件销毁。

销毁前，有人注意到纸条背面还有一行小字，是林默的手写：

"2026.3.23，古法组最后一次全员会议。今日起，我们成为濒危物种。"

## 尾声：六个月后的面试
李想坐在面试官的位置，对面是一个23岁的应届生。简历上写着："AI原生开发者，100%代码生成采纳率，零古法训练背景。精通Opus 9.9-10.2全系列工具链。"

"最后一个问题，"李想说，"如果AI告诉你置信度99%，但你感觉不对劲，你会怎么办？"

应届生困惑地看着他。"感觉？AI的置信度是基于统计的，比人类直觉可靠。如果感觉和AI冲突，应该检查自己的认知偏差。另外，根据我的训练数据，2026年之后已不存在'古法验证'的替代方案，所以这个问题在技术上不成立。"

李想点点头，在评估表上勾选"符合岗位要求"。然后他停顿了一下，在备注栏手写："建议入职后关注'古法兴趣小组'（如有）。"

他知道这个小组不存在。公司里的古法程序员数量是0，全球是1.2万且持续下降。但他需要写下这句话，以便在未来的某个凌晨，当自己也对着屏幕发抖时，能想起曾经有人知道该怎么办。

面试结束后，他路过那个"AI协作体验角"。屏幕上的林默形象正在循环播放，讲解着2026年的历史。他停下来，看了很久。

"你在想什么？"周婷路过，问他。

"想2026年，"李想说，"那时候还有十二个人，会围在一起看终端输出的滚动日志。像老中医把脉一样。"

周婷沉默了一会儿。"那时候效率很低吧？"

"嗯，"李想说，"但那时候，如果系统病了，有人知道怎么把脉。"

他们一起看着屏幕上的林默形象，AI生成的，完美还原了2026年的样子，但不会变老，不会离职，也不会在凌晨3点对着崩溃的系统无能为力。

"他走了之后，"周婷问，"我们怎么办？"

李想没有回答。他想起林默说过的话："你们不是在优化效率，你们是在拆除逃生通道。"

现在通道拆完了，他们在高楼里，等待下一次地震。
